# ARA Self Rec — Reconciliation Run JSON Contract

**Contract version:** 1.0.0  
**Status:** Stable draft — not yet wired to frontend or Python engine

---

## Purpose

This document defines the shared JSON payload used to describe a complete
reconciliation run configuration.  The same structure is used by:

| Consumer | Role |
|----------|------|
| Angular frontend | Produces the payload from the Upload → Mapping → Passes → View wizard |
| Python backend engine | Reads the payload and executes the reconciliation |
| TypeScript backend (current) | Continues to use `RunRequest` — **not replaced** |

The contract is intentionally simple and flat so that it can be hand-authored,
generated by the UI wizard, or produced programmatically.

## Top-level structure

```json
{
  "metadata":  { ... },
  "sources":   { "left": { ... }, "right": { ... } },
  "mapping":   { "pairs": [ ... ] },
  "passes":    [ ... ],
  "view":      { ... },
  "execution": { ... }
}
```

---

## A. `metadata`

Identifies and describes the run submission.

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `contractVersion` | string | ✓ | Semantic version, e.g. `"1.0.0"` |
| `runName` | string | ✓ | Human-readable label |
| `runMode` | `"preview"` \| `"execute"` | ✓ | `preview` = dry-run; `execute` = committed results |
| `submittedBy` | string | ✓ | User ID or email |
| `createdAt` | ISO-8601 string | ✓ | e.g. `"2026-03-30T09:00:00Z"` |
| `description` | string | — | Optional free-text |

---

## B. `sources`

Describes the two input files.  Each side has the same shape.

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `uploadId` | string | — | ID returned by the upload endpoint after file upload |
| `label` | string | ✓ | Display name, e.g. `"Front Office Extract"` |
| `fileName` | string | ✓ | Original file name |
| `fileType` | `csv` \| `xlsx` \| `tsv` \| `json` | ✓ | |
| `sheetName` | string | — | xlsx only |
| `delimiter` | string | — | csv/tsv only; defaults to `","` |

`sources.left` = historically "Source A"; `sources.right` = historically "Source B".

---

## C. `mapping`

An ordered list of field pairs linking left-source columns to right-source columns.

### `mapping.pairs[]`

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `leftField` | string | ✓ | Column name in the left source |
| `rightField` | string \| null | ✓ | Matching column in the right source; `null` = explicitly unmapped |
| `required` | boolean | ✓ | If `true` the run cannot proceed without this pair |
| `transformation` | object | — | Normalisation applied to both values before comparison |

### `transformation`

| Field | Type | Notes |
|-------|------|-------|
| `type` | `trim` \| `uppercase` \| `lowercase` \| `date_format` \| `numeric_round` | |
| `params` | object | Optional — e.g. `{ "format": "YYYY-MM-DD" }` or `{ "decimalPlaces": 2 }` |

---

## D. `passes`

An ordered array of reconciliation passes.  The engine evaluates passes in
`priority` order (lowest number first).

### `passes[]`

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `passId` | string | ✓ | Stable ID, e.g. `"PASS-001"` |
| `name` | string | ✓ | Human-readable label |
| `type` | `exact` \| `tolerance` \| `manual` | ✓ | Algorithm category |
| `priority` | number | ✓ | Execution order; 1 = highest |
| `enabled` | boolean | ✓ | Excluded from the run when `false` |
| `stopOnMatch` | boolean | ✓ | If `true` a matched row skips lower-priority passes |
| `rules` | array | ✓ | Match conditions (all must pass) |
| `tolerance` | object | — | Required when `type` is `"tolerance"` |
| `description` | string | — | Optional |

### `passes[].rules[]`

| Field | Type | Notes |
|-------|------|-------|
| `leftField` | string | Column in the left source |
| `operator` | `eq` \| `contains` \| `starts_with` \| `numeric_abs` \| `numeric_pct` | |
| `rightField` | string | Column in the right source |

### `passes[].tolerance`

| Field | Type | Notes |
|-------|------|-------|
| `type` | `absolute` \| `percentage` | |
| `value` | number | Absolute unit (e.g. `0.01`) or percentage (e.g. `1.0`) |

---

## E. `view`

Controls how results are displayed in the Angular result grid.

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `name` | string | — | Optional saved view label |
| `columns` | array | ✓ | Ordered list of result columns |
| `sort` | object | — | Primary sort: `{ field, direction }` |
| `groupBy` | object | — | Grid grouping: `{ field, showSubtotals }` |
| `summaryCards` | string[] | ✓ | Cards to show: `"matched"`, `"unmatched"`, `"breaks"`, `"exceptions"`, `"match_rate"` |
| `visibleCategories` | string[] | ✓ | `"matched"`, `"unmatched"`, `"exceptions"`, `"breaks"` |

### `view.columns[]`

| Field | Type | Notes |
|-------|------|-------|
| `field` | string | Logical field name |
| `source` | `"left"` \| `"right"` \| `"both"` | Which source side |
| `visible` | boolean | |
| `label` | string | Optional display-label override |

---

## F. `execution`

Run-level engine settings.

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `matchStrategy` | `first_match` \| `best_match` \| `all_matches` | ✓ | How multi-pass hits are resolved |
| `allowPartialMatch` | boolean | ✓ | Match on a subset of mapped pairs |
| `generateBreakReport` | boolean | ✓ | Emit a structured break report |
| `generateAnalyzerReport` | boolean | ✓ | Run AI analyzer and attach narrative |
| `maxPreviewRows` | number | — | Row cap for preview runs |

### `matchStrategy` values

| Value | Behaviour |
|-------|-----------|
| `first_match` | Stop at the first pass that produces a match — fastest |
| `best_match` | Evaluate all passes; pick the highest-confidence match |
| `all_matches` | Report every pass that matches (may produce multiple rows per pair) |

## How the frontend produces this payload

The Angular wizard already collects all the necessary data across its steps:

| Wizard step | Contract section |
|-------------|-----------------|
| Upload | `sources.left`, `sources.right` |
| Mapping | `mapping.pairs` |
| Passes | `passes` |
| View | `view` |
| Run dialog | `metadata`, `execution` |

When the "Run" button is pressed, the component assembles a `ReconRunPayload`
object (typed via `recon-run-contract.models.ts`) and posts it to the future
Python endpoint.  The existing `RunRequest` / `SelfRecRunService` path
continues to be used for the TypeScript backend and is not changed.

---

## How the Python backend consumes this payload

```python
from models.recon_run_contract import ReconRunPayload
import json

with open("run_payload.json") as f:
    data = json.load(f)

payload = ReconRunPayload.model_validate(data)

# Access sections
print(payload.metadata.run_name)
print(payload.sources.left.file_name)
for pair in payload.mapping.pairs:
    print(pair.left_field, "->", pair.right_field)
for p in payload.passes:
    if p.enabled:
        print(f"Pass {p.pass_id}: {p.name}")
```

## Versioning

The `contractVersion` field in `metadata` is a semantic version string.
Breaking changes (renamed fields, removed sections) must increment the major
version.  Additive changes (new optional fields) warrant a minor bump.
The Python and TypeScript models carry the same version comment so both sides
stay aligned.
